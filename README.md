# Time Bracket

여섯 명의 동료가 각자의 가능·부담·불가능 시간을 공유하고, 시스템의 설명 가능한 선별 과정을 거쳐 1시간 회의를 확정하는 SwiftUI 프로토타입입니다.

## 해결하려는 문제

기존 일정 조율은 가능한 시간을 겹쳐 보여주는 데 그치기 쉽습니다. 하지만 실제 회의에서는 필수 참석자 여부, 이동이나 일정으로 인한 부담, 선택 참석자의 불참 가능성까지 함께 판단해야 합니다.

Time Bracket은 다음 질문에 답하도록 설계했습니다.

- 누가 반드시 참석해야 하는가?
- 참석은 가능하지만 부담스러운 시간은 언제인가?
- 어떤 후보가 제외되었고, 그 이유는 무엇인가?
- 남은 두 후보 중 왜 한 시간이 더 안정적인가?

## 핵심 플로우

1. 홈에서 새 회의 조율을 시작합니다.
2. 후보 기간, 회의 정보, 필수·선택 참석자를 설정합니다.
3. 주최자가 09:00-18:00 시간표에 가능·부담·불가능을 입력합니다.
4. 부담·불가능 시간에는 팀원이 이해할 수 있는 사유를 남깁니다.
5. 일정을 공유하고, 여섯 명의 응답 진행 상황을 캘린더에서 확인합니다.
6. 전원 응답 후 시간대 선호와 피할 시간을 선택합니다.
7. 시스템이 기준 적용, 필참 확인, 부담 비교, 바로 참석 비교, 대표안 선정 순서로 후보를 좁힙니다.
8. 주최자가 추천안과 차순위안을 비교하고 한 시간을 확정합니다.
9. 체크·컨페티 피드백 뒤 확정 회의가 캘린더와 홈에 반영됩니다.

## 선별 원칙

| 순서 | 판단 내용 |
|---|---|
| 기준 적용 | 주최자가 정한 시간대 선호와 제외 시간을 반영 |
| 필참 확인 | 필수 참석자가 불가능한 후보를 우선 제외 |
| 부담 비교 | 부담 인원과 사유별 가중치를 함께 비교 |
| 바로 참석 비교 | 별도 조정 없이 참석 가능한 인원이 많은 후보를 우선 |
| 대표안 선정 | 시간대 선호와 인접 시간 안정성까지 반영해 최종 2안 추천 |

부담은 `일정 3`, `이동 3`, `개인 2`, `집중 1`의 상대 가중치로 비교합니다. 점수는 사용자를 평가하기 위한 값이 아니라, 같은 인원수의 부담이 있을 때 조정 난이도를 비교하기 위한 내부 기준입니다.

## 구현 환경

- SwiftUI
- iOS 17+
- 외부 라이브러리 없음
- 로컬 상태와 시연용 더미 데이터 사용
- 백엔드, 네트워크, 실제 초대·응답 연동 없음

## 실행

1. `Time Bracket.xcodeproj`를 Xcode에서 엽니다.
2. `Time Bracket` 스킴과 iOS 17 이상 시뮬레이터 또는 실기기를 선택합니다.
3. Run으로 실행합니다.

## 프로토타입 범위

현재 버전은 제출 영상에서 핵심 경험을 검증하기 위한 고충실도 프로토타입입니다.

- 공유 채널 선택 이후의 전송은 시뮬레이션입니다.
- 참석자 응답은 실제 입력처럼 순차적으로 보이는 결정적 데모 데이터입니다.
- 회의 확정 결과는 로컬 상태로 홈과 캘린더에 반영됩니다.
- 실제 캘린더 충돌 자동 감지, 알림, 서버 동기화는 후속 범위입니다.
